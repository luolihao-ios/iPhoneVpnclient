# Windows 托盘与代理分流一致性设计

## 目标

让 Windows 端继续使用现有 sing-box CLI，同时补齐移动端的全局代理、智能分流和桌面生命周期行为。界面文案和内容保持一致，布局采用 Windows 桌面布局。

## 行为

- 全局代理：连接成功后将当前用户的 Windows 系统代理设置为 `127.0.0.1:2080`，sing-box 使用 global 路由。
- 智能分流：同样启用系统代理，但 sing-box 使用 rule 路由；国内域名/IP直连，其余流量代理。
- 断开、托盘退出或核心异常退出时恢复连接前保存的系统代理设置。只有当注册表仍保持 Forge VPN 写入的值时才恢复，避免覆盖用户之后手动修改的设置。
- Windows 不启用移动端 TUN；不遵循系统代理的应用不承诺被接管，并在设置/诊断中保留现有提示。
- 点击窗口关闭按钮只隐藏到系统托盘，托盘双击恢复窗口；托盘菜单提供“显示 Forge VPN”和“退出”。真正退出前执行代理恢复和核心清理。
- Windows 导航栏只保留仪表盘、设置、日志，移除导航栏内重复的 Forge VPN 品牌块，顶部 AppBar 保留品牌。

## 架构

- 新增 Dart `WindowsProxyService`，封装当前用户 Internet Settings 注册表值的读取、写入、条件恢复和测试注入接口。
- `AppProvider` 在 Windows 核心连接成功后启用系统代理，断开/异常/销毁时恢复；路由模式继续通过现有 sing-box 配置生成器传入。
- Windows runner 增加原生 Win32 托盘图标和菜单。`WM_CLOSE` 仅隐藏窗口，托盘“退出”切换为真正退出并销毁窗口；图标使用已有 `resources/app_icon.ico`。

## 错误处理

- 注册表读写失败不阻止核心启动，但在运行日志和 `proxyWarning` 中报告。
- 核心启动失败时不启用系统代理。
- 代理恢复失败只记录警告，不能阻止窗口退出。

## 测试

- Dart 单元测试覆盖：保存原始注册表快照、写入 2080、条件恢复、用户改动后不覆盖、异常路径。
- 现有 sing-box、诊断测试继续通过。
- Windows runner 通过人工验证：关闭隐藏、托盘双击恢复、托盘退出；构建命令由用户在已配置的 VS 环境执行。
