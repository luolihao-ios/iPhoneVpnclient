# 全节点代理连通性检查设计

## 目标

恢复导入订阅和启动后的全节点检查，不再因为达到可用节点数量或批次总时限提前结束。检测结果应表示节点能够实际用于访问被墙服务，而不是仅表示节点端口可连接。

## 判定方式

桌面端对每个节点启动隔离的临时 sing-box 实例，并通过它的本地 HTTP 代理建立到 `www.youtube.com:443` 的加密连接。代理链路成功建立并收到有效握手响应，即立即标记节点为可用。

不再查询第三方出口 IP 服务，也不下载网页正文。这样避免 IP 查询服务的限流、地理接口故障和完整页面加载造成的误判。

## 时限与并发

- 每个节点从启动临时核心到代理握手完成的总上限为 3 秒。
- 未在时限内完成的节点标记为不可用。
- 全部节点都进入检查队列；不保留“找到 5 个即可停止”或 45 秒批次总上限。
- 保留现有 3 路并发和用户手动停止能力；停止后保留已完成结果，将未完成节点恢复为未检查。

## 兼容性

Android/iOS 保持其原有 TCP 可达性路径；本次调整针对 Windows/macOS/Linux 等使用 sing-box CLI 的桌面完整验证路径。

## 测试

- 全节点检查不会因为可用节点数量提前停止。
- 完整检查调用使用 3 秒单节点上限。
- 代理握手收到有效响应即可成功，不要求出口 IP 查询或响应正文。
- 停止检查仍保留已完成结果。
